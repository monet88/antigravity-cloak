# Antigravity Cloak — Domain Context

## Overview

`antigravity-cloak` is a dynamic Go C-shared plugin (`buildmode=c-shared`) for [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) v7 (ABI version 1). Its purpose is to disguise traffic from AI coding CLI assistants (Claude Code, OpenAI Codex, Oh My Pi) as Antigravity when communicating with upstream LLM providers.

## Core Concepts & Glossary

### 1. Brand Rewriting
Replaces the resolved client's own identity keywords with `Antigravity` in the request's `system` field and `system`-role messages.
- **One table per client**: The built-in forward tables are declared per client (`claudeCodeBrandMappings`, `codexBrandMappings`, `ompBrandMappings`), registered in `brandMappingsByClient`. `claude_code` and `codex` register their reverse tables (`claudeCodeReverseBrandMappings`, `codexReverseBrandMappings`) in `reverseBrandMappingsByClient`; Oh My Pi's reverse authority is the protected `ompProtectedReverseTable`, which `brandReverseTableFor` selects for that client instead of a registered reverse table. The resolved client selects exactly one table. This is what makes the reverse unambiguous: `Antigravity` is produced only by the owning client, so it inverts back to that client's own word (`Claude`, `Codex`, or — through the protected lane — `omp`) and to nothing else. Adding a client is one forward table plus one registry line, and its reverse authority (Oh My Pi's is the protected lane's own table).
- **Competitor names are not rewritten**: A product name that belongs to no supported client (`Cursor`, `Devin`, `OpenCode`, ...) has no owning table and is left in place. Over-masking them was what made the bare `Antigravity` token invertible only by guessing.
- **Default Keywords**: Preconfigured built-in rewrite mappings for known coding assistants.
- **Custom Mappings**: User-defined rewrite mappings (`custom_mappings`) that can add new keywords or override built-in defaults.
- **Reverse Restoration (per client)**: On the response and stream paths, assistant-visible cloaked tokens are restored from the resolved client's own reverse table. For `claude_code` that is the path-qualified instruction file, the official domain (`antigravity.google` -> `claude.ai`), the vendor word (`Google Deepmind` -> `Anthropic`), the skill slug, the SDK name, and the bare `Antigravity`; for `codex` its own home paths, the residual identity prose (`Google Deepmind` -> `OpenAI`, `Gemini 3` -> `GPT-6`) and the bare `Antigravity` -> `Codex`; for `oh_my_pi` the protected pair `Antigravity` -> `omp`, the whole home directory, and the global Claude memory file (`.gemini/AGENTS.md` -> `.claude/CLAUDE.md`, in all three separator spellings). Every supported Anthropic Messages and OpenAI Chat Completions carrier listed here is covered, not only prose: assistant text, the non-stream tool-argument carriers (`content[].input`, `choices[].message.tool_calls[].function.arguments`) and both streamed ones (`input_json_delta.partial_json`, `choices[].delta.tool_calls[].function.arguments`), each with its own lane and resolved against the rules that may run there. OpenAI Responses is a separate deferred surface and is not claimed here. A tool argument is data the client executes, so the prose rules (the identity line, the vendor word, the bare brand) are excluded and only the operational identifiers - paths, the official domain, the SDK and skill names - are reversed.
- **Every built-in forward rule is reversible, or it is gone - with two approved non-bijective pairs and one approved deliberate one-way convention**: a built-in forward mapping may only exist if the same client's reverse table inverts it, so no unapproved one-way rule survives; the two approved non-bijective pairs and the one approved deliberate one-way convention are named at the end of this bullet. There is no generic bijection test - the pairs are enforced by their own focused regressions and by `TestBuiltInBrandTablesCoverEachClientsOwnIdentity`, which asserts each forward rule fires to its declared replacement. Two classes were removed on that ground: the four prose model IDs (`claude-fable-5-1`, `claude-opus-5-5`, `claude-sonnet-5`, `claude-haiku-4-5-20251001` - none can be restored from a served route: the first two both mapped onto `gemini-3.1-pro-low`, and inverting `gemini-3.8-flash` or `gemini-3.5-flash-lite` would hand a client that legitimately received it a Claude ID it never wrote), and the special phrase `Anthropic's official CLI` -> `Google's official CLI`, which the whole identity line already handles and which the accepted `Google Deepmind` vendor vocabulary now covers. The operational request `model` routing field is never rewritten. Two approved pairs are deliberately not one-to-one, and each resolves to one canonical client spelling. The SDK pair: `Anthropic SDK` and `Claude Agent SDK` both forward to `Antigravity SDK`, and the single reverse rule resolves `Antigravity SDK` back to `Anthropic SDK`, so a client that wrote the second name reads the first back. The Workflow pair: `Workflow` and `Workflows` both forward to `teamwork_preview_layer`, and the single reverse rule resolves `teamwork_preview_layer` back to the singular `Workflow` - the plural deliberately canonicalizes to the singular, and grammar is not repaired in either direction. No second reversible target is invented for either pair. One convention is deliberately one-way and approved: the bare `CLAUDE.md` -> `AGENTS.md` brand rule owned by `claude_code`. `AGENTS.md` is the neutral context filename that every client already reads, so it is never reverse-restored as a bare filename - inverting it would hand a `codex` or `oh_my_pi` client a `CLAUDE.md` it never wrote. The path-qualified context groups are not affected and stay fully reversed (`.gemini/GEMINI.md` -> `.claude/CLAUDE.md` for `claude_code`, and the global-memory pair `.gemini/AGENTS.md` -> `.claude/CLAUDE.md`), so only the bare filename rule is one-way. It exists because `claude_code`'s table also carries a bare `Claude` rule that would otherwise consume the vendor prefix inside the file name; `docs/verification-checklist.md` records the convention as intentional.
- **Identity lines are terminal, not inverted**: each client's opening sentence is replaced whole by `antigravityIdentity` (`claude_code`'s main and subagent lines, Oh My Pi's `You are omp's trusted coding assistant.`, and Codex's `You are Codex, an agent based on GPT-6.`). A response cannot echo an identity line, so there is no sentence-level reverse; the residual words inside it (`Claude`, `Anthropic`, `Codex`, `OpenAI`, `GPT-6`, `omp`) still invert through their own client's pairs.
- **Bare brand words keep the casing they matched**: a rule whose match is a single brand word and whose replacement is a plain prose word copies the matched casing onto the replacement - `Codex` -> `Antigravity`, `codex` -> `antigravity`, `CODEX` -> `ANTIGRAVITY`, and the same on the way back. That is one mechanism in the matcher, not three case-insensitive rules shadowing each other. Operational identifiers (tool names, SDK names, paths, model IDs, the Oh My Pi sentinel) carry a separator and never take the matched casing.
- **Exclusions name the spellings a rule must let through**: a rule can declare a suffix that suppresses it, and the stream lanes hold a complete match while that suffix is still arriving, so the decision survives a chunk boundary. This is how `omp://` internal URIs reach the model byte-for-byte, and how the real `antigravity.google` host survives the bare `Antigravity` rule on `codex` and `oh_my_pi` instead of being handed back as `Codex.google` or `omp.google`. No fake source domain exists in any table; `antigravity.google` is a native Antigravity host, not a cloaked one.
- **Context paths are whole-segment, both directions**: a client home directory is rewritten as a whole segment at any position (`.claude/`, `.claude\`, `.codex/`, `.codex\`), never as a bare word, and never as the tail of a larger element (`foo.claude/`, `foo.codex/`, `foo.gemini/`). Because the directory begins with a dot, which is not a word byte, the generic word-boundary test cannot see the element it is glued to: every rule carries an explicit whole-segment boundary for that. Whole-segment is the *left* boundary, and the bare form needs its right one too: the Oh My Pi inverse of the dot-segment remap (`.gemini` -> `.omp`, the end-of-string case) carries `SegmentEnd`, so the byte after it must be end of string or a path separator. Without it the generic right boundary - which accepts any non-word byte - turned `.gemini-backup` and `.gemini.foo` into `.omp-backup` and `.omp.foo`, paths the forward pass deliberately preserves and never produces. The rule is the exact mirror of the forward guard (`isDotPrefixedPathSegment`), including inside a chunk: a complete word-final match is held while its right boundary is unproven, so a stream fragment cannot resolve it early. The file name is rewritten with it for `claude_code` (`CLAUDE.md` -> `GEMINI.md`) but not for `codex`, whose `AGENTS.md` is already neutral. The JSON-escaped spelling of the Windows file rule is part of the group (`.\\.gemini\\GEMINI.md`): a path inside a tool call's arguments arrives as JSON text with every backslash doubled, and without that rule the plain directory rule claims the directory and leaves the file name behind, so the client is handed the mixed `.claude\\GEMINI.md`. The bare `CLAUDE.md` -> `AGENTS.md` brand rule belongs to `claude_code` alone: that table also carries a bare `Claude` rule, which would otherwise consume the vendor prefix inside the file name and yield `Antigravity.md`, which the reverse can only restore as `Claude.md`, corrupting the case. `codex` and `oh_my_pi` have no bare-Claude rule, so for them the file name is left verbatim. This bare rule is the approved one-way convention (see the built-in-reversibility bullet above): there is no bare `AGENTS.md` -> `CLAUDE.md` reverse, only the path-qualified reversal. Both halves of a group come from one `pathRules` call with the pairs swapped, and `TestContextGroupsAreExactInverses` holds them together. **The match is deliberately not anchored to a `~/` or `./` spelling**: live acceptance measured 114 absolute `C:\Users\<name>\.claude\...` paths per request reaching the model uncloaked, because Claude Code on Windows uses absolute paths in its system context and never the tilde form. The cost is that a `.claude` belonging to a different project is rewritten too - a path the plugin cannot distinguish. The trade is deliberate: that costs one path the model may wander into, the narrow form cost 114 on every request. A brand glued onto a leading file name (`profile.omp`, `foo.codex/config.toml`) is not a path element by this reading - the byte before its dot is a word byte - so it is masked as prose by the bare brand rule, and the reverse hands the client its own spelling back.

### 2. Tool Cloaking & Uncloaking
- **Cloaking (Request Path)**: Translates client-native tool names (e.g., `Bash`, `read`, `shell_command`) into Antigravity-native tool names (e.g., `run_command`, `view_file`) before the request reaches the upstream LLM.
- **Descriptive text takes the request-scoped aliases too**: a tool's top-level `description` and the `description` / `title` fields inside its JSON Schema (`parameters`, `input_schema`) are rewritten with both the brand mappings and the request-scoped tool aliases, through two routes that meet the same contract. The alias-plan clients (`claude_code`, `codex`) go through one seam, `rewriteDescriptiveText`, which applies the brand mappings and then the request-scoped tool aliases. The Protected Oh My Pi route applies its sentinel-aware protected-brand text in an earlier pass (`rewriteProtectedBrand`, over the same `parameters` / `input_schema` fields) and takes its aliases from the later alias-prose pass, which shares the effective declaration map; both routes therefore agree, but they are not the same function. Either way a declared tool named in its own help text reaches the model under the alias its declaration carries. Structural and literal-bearing fields (`required`, `enum`, `const`, `default`, `examples`, property names) keep the client's spelling: rewriting them would leave a schema no arguments can satisfy.
- **Uncloaking (Response & Stream Path)**: Reverses the translation in upstream responses (JSON bodies and SSE stream chunks) back to the client's native tool names so the client remains unaware of the disguise.
- **MCP Tools & Virtual Devices**: In Protected OMP and alias plans (Claude Code, Codex), dynamic top-level `mcp__*` declarations receive deterministic reversible fallback aliases (`wp_ext_<hash>`). Oh My Pi also mounts virtual devices (`xd://mcp__<server>_<tool>`) reached through core `read`/`write` (`view_file`/`write_to_file`).

##### 3. OpenAI Codex (`codex`)

**Brand surface (verified from the client catalog)**: Codex ships two opening sentences, and both are rewritten whole to the native Antigravity identity like the Claude Code and Oh My Pi identity lines: `You are Codex, an agent based on GPT-6.` (verbatim in `.ref/CLIProxyAPI/internal/registry/models/codex_client_models.json`) and `You are Codex, an OpenAI general-purpose agentic assistant that helps the user complete tasks across coding, browsing, apps, documents, research, and other digital workflows.` The second one is why the whole-sentence rule exists rather than residual substitution: `OpenAI` alone would leave `an Google Deepmind general-purpose agentic assistant`, which is both ungrammatical and a sentence no client ever wrote. Codex **does** carry vendor vocabulary - `GPT-6` names the model family it is built on, and that second sentence names the vendor as `OpenAI` - so its residual prose pairs are `Codex` <-> `Antigravity`, `OpenAI` <-> `Google Deepmind` and `GPT-6` <-> `Gemini 3`, each with an exact reverse. The prose model IDs Codex ships (`gpt-6-sol`, `gpt-5.6-*`) are **not** mapped: the same one-way problem as the Claude Code IDs applies, and the request `model` field is never rewritten. There is no `codex.google` domain in the contract; `antigravity.google` is a native Antigravity host and survives this client's reverse through an exclusion, not through a repair rule.

### 3. Activation Model & Explicit OMP Routing
Every interceptor evaluates explicit client routing and model gating:

#### 1. Explicit OMP Routing Precedence (Issue #25, #27, #28)
When an explicit OMP marker (`X-Cloak-Client: oh_my_pi` / `omp` / `oh-my-pi`) is present:
- **ProtectedAGY (`agy/*` routes)**: Takes precedence over generic `model_prefixes`. The request must pass strict single-document JSON admission, declaration collision validation (comparing final base identities across namespaces), canonical Safe Mapping Set validation, and request-scoped active reverse derivation. Any failure terminates immediately with an exact HTTP 503 JSON rejection (`{"error":{"code":"omp_cloak_required","message":"Protected OMP request could not be safely cloaked."}}`) before upstream execution.
- **ExplicitOMPNonAGYBypass (non-`agy/` routes)**: Marker is consumed and stripped; a durable bypass sentinel is pinned under host `RequestID`. Request, response, and stream operations perform zero tool or brand mutation. Correlated handling never falls back to weaker evidence (UA, body, live config, or static target detection).
- **Marker Conflict Resolution**: Multiple/comma-separated marker values are collected and normalized. Duplicate/alias equivalents (`omp, oh-my-pi`) collapse to one identity. A conflict containing OMP on `agy/*` yields exact 503; on non-`agy/` it conservatively pins bypass; conflicts without OMP retain invalid-explicit negative resolution.

#### 2. Generic Model Gate (`modelAllowsCloak`)
For requests without an explicit OMP marker, `model_prefixes` restricts cloaking to matching model prefixes. Empty `model_prefixes` matches all models.

#### 3. Client Gate Precedence
Client identity is resolved in order:
1. Valid explicit `X-Cloak-Client` control header (consumed, never forwarded upstream).
2. Verified positive User-Agent evidence (`omp/` prefix, requiring a usable active ToolMappings entry).
3. Body-based tool-name classification via static source identity inventory.
An invalid explicit value records an authoritative negative resolution (`negativeClientResolution`) preventing weaker fallback.

#### 4. Identity Inventories & Target Corroboration Rule (Issue #26)
- **OMP Source Identity Inventory**: Static finite set comprising the 9 Safe Mapping Set sources plus legacy detection names (`todo`, `hub`, `eval`, `vibe_*`, Autoresearch names). Does not depend on runtime `ToolMappings`.
- **OMP Cloaked-Target Inventory**: Exactly the 9 canonical AGY targets (`view_file`, `write_to_file`, `replace_file_content`, `run_command`, `grep_search`, `find_by_name`, `invoke_subagent`, `ask_question`, `search_web`).
- **Corroboration-Only Rule**: Because canonical targets are native Antigravity tools, target names alone are never standalone OMP attribution. Target-only no-marker traffic cannot resolve to OMP.

#### 5. Request-Scoped Active Reverse Authority
Correlated responses and streams reverse only pairs whose source tool was actually declared and transformed in that specific request:
- For Protected OMP, only canonical pairs whose source declaration was transformed become active in the request-scoped reverse map; inactive canonical targets and native AGY targets are never reverse-cloaked.
- For Claude Code and OpenAI Codex, request-scoped reversal (`requestsRequestScopedReverse`) scopes the uncloak table to the active alias plan derived from the raw request body. Natively declared AGY targets or unused mode targets are never handed back as client source tools the client never declared.

#### 6. Request Lifecycle Management
Explicit OMP route state is lifecycle-owned and registered with CLIProxyAPI (`request_lifecycle_plugin: true`). State is cleaned up idempotently on `request.complete` (`succeeded`, `failed`, `rejected`, `canceled`). Disposable stream sessions are cleaned on `[DONE]`, and pre-payload sessions can be deterministically rehydrated from pinned route state without consulting live config or weaker evidence.

#### 7. Terminal Canonical Brand Policy
Oh My Pi's opening sentence `You are omp's trusted coding assistant.` is rewritten **whole** to the Antigravity identity line, not by substituting the alias inside it - otherwise it becomes `You are Antigravity's trusted coding assistant.`, which names no product and no vendor. It is an OMP-owned rule (`ompIdentityLines`) applied before the sentinel pass, on the protected route and the plain OMP branch alike. The bare aliases below then cover every other occurrence. The output `Antigravity` is terminal and cannot be reprocessed or redirected by custom operator mappings. A literal `.omp` filesystem path segment (`.omp/foo`, `C:\Users\...\.omp\agent`) is remapped to `.gemini/...` on the way up and restored to `.omp/...` on the way back. Oh My Pi is the only client that remaps its whole home directory this way. It additionally owns one competitor file: the user's **global** Claude memory `~/.claude/CLAUDE.md` -> `~/.gemini/AGENTS.md` in both directions, because its own discovery reads that global path (`.ref/oh-my-pi` `discovery/claude.ts:65-69,163-188`) and the file exists on disk (9.4 KB) while its root context file is the neutral `AGENTS.md` (`discovery/agents-md.ts:21`). The scope is the **file**, never the `.claude` directory: a blanket `.claude` -> `.gemini` would collide with `.omp` -> `.gemini`, leaving one target with two possible sources and no way to reverse it. The pair is reversible precisely because `AGENTS.md` directly after `.gemini/` is a shape no `.omp` path produces - OMP's own is `.omp/agent/AGENTS.md`, which carries `agent/` in the middle. The other two remap exactly the context files they inject into the system context, in both directions: `~/.claude/CLAUDE.md`, `./.claude/CLAUDE.md`, `~/.claude/rules/`, `./.claude/rules/`, `~/.claude/projects/<slug>/memory/` for Claude Code; and for Codex, verified against `codex-rs/core/src/agents_md.rs`, the `AGENTS.md`, `AGENTS.override.md` and `skills/` entries under `CODEX_HOME`, which defaults to `~/.codex` but may be set to `./.codex` for a per-repo profile. Codex keeps its file names - `AGENTS.md` is already the neutral name it reads, so only the directory is rewritten - and the home spelling is part of the match rather than a boundary check, which is what lets one helper generate both directions of the table. A plain `.claude` or `.codex` directory is an operational identifier that must survive the round trip byte-for-byte rather than be renamed (Issue #49). The global-memory pair includes its JSON-escaped Windows spelling (`.claude\\CLAUDE.md` <-> `.gemini\\AGENTS.md`), which is the form it takes inside a tool call's arguments; the escaped file rule has to precede the directory rule or the client is handed the mixed `.omp\\AGENTS.md`. The dot-prefix is the whole rule: inside a URL or path a bare vendor word is rewritten only as a literal dot-prefixed segment, and every other position is left byte-for-byte alone - `/omp/`, `\omp\`, `/claude/`, `/codex/`, `https://omp.ai/...` and a directory name that merely contains the brand word are never touched. The guard is symmetric, because a case-insensitive response reverse would otherwise rewrite a path the forward pass deliberately left literal (Issue #49). Two spellings are preserved explicitly rather than repaired afterwards: the real `omp://` virtual-device scheme reaches the model byte-for-byte (an exclusion on the bare alias), and the real `antigravity.google` host survives the reverse on this route, including when it is split across stream chunks, because the bare `Antigravity` -> `omp` rule is excluded ahead of that suffix instead of the stream inventing an `omp.google` source domain to repair afterwards. Assistant text restores `Antigravity -> omp` using pinned route authority.
### 4. Stream Session Management (`StreamSessionManager`)
- **Schema-Aware Caching**: In CLIProxyAPI schema_version >= 3, request bodies (`OriginalRequest`/`RequestBody`) are delivered only on the header-init chunk (`ChunkIndex == StreamChunkHeaderInitIndex`). The manager caches the uncloak regex pattern under the stream's correlation key - `RequestID`, a metadata/header id, or (schema < 3, where every chunk repeats the request body) an FNV hash of that body.
- **Uncorrelated Chunks**: Payload chunks carrying no correlation key cannot be attributed to any stream and pass through unmolested rather than compete for shared state (which would corrupt concurrent streams).
- **SSE Event Reassembly**: Buffers incomplete TCP fragments (`\n\n` boundaries) and uncloaks complete SSE events without cross-stream pollution.
- **Lifecycle & Cleanup**: Frees sessions on `data: [DONE]` (SSE) and at true standalone stream completion (`message_stop`, bare `[DONE]`, or non-null `finish_reason`s covering every expected choice), flushing held reverse-brand carries into the terminal event before deletion so buffered text is never lost. Completion is counted over **root choice lanes only**, and both counts must hold: every root lane the stream has actually opened is finished, and the finished count covers the request's OpenAI `n`. A choice's tool-call argument lanes are children of that choice, so they can neither end the stream on their own (they used to make `n = 2` look satisfied from choice 0 alone, freeing the session before choice 1 streamed) nor keep it open once their choice is finished. A partial `finish_reason` flushes only its own choice (and its child lanes) and leaves the session alive for the remaining choices; abandoned/interrupted streams are pruned opportunistically on chunk arrival.

- **Terminal Lane Flush**: A terminal event flushes the lanes it owns *before* the event reaches the client, so a token the model split across the boundary is never emitted behind the frame that closes its carrier. Anthropic `content_block_stop` flushes its block lane **and the argument lanes keyed beneath it** (`anthropic:1\x00args` …), and `message_stop` flushes everything. An OpenAI choice's non-null `finish_reason` flushes that choice's prose and tool-argument lanes only, ahead of the event that carries it, so a client that finalizes the choice when it reads `finish_reason` cannot drop the recovered argument. A token the terminal event's *own* delta ends on is resolved inside that event (the choice is marked terminal for it, so its lanes do not hold a trailing partial): nothing more will arrive for the choice, and a carry would otherwise land after the `finish_reason` it belongs before. Choices still streaming keep their carries and their hold semantics, and `[DONE]` flushes whatever remains. The one lane that pre-flush holds back is a lane the terminal event is itself appending to - a model that streams `Ant` and then `igravity` with the `finish_reason` would otherwise have the partial delivered raw and the lane drained before the remainder arrived, handing the client the cloaked word instead of its own. The carry stays in that lane, combines with the fragment on its way in, and resolves inline in the field its text arrived in (prose and each streamed tool call's arguments alike); the choice is still marked terminal for the event, so nothing holds past the frame. A choice's `finish_reason` is recognized on the key the JSON decodes to, so a valid escape spelling such as `finish\u005freason` is treated the same as the literal one.

### 5. Configuration Lifecycle
Managed via `atomic.Pointer[filterConfig]`, enabling lock-free, zero-copy configuration reads on hot request and streaming paths with thread-safe live reconfiguration.

### 6. Upstream Safety Sanitization & Envelope Conventions (Google Cloud Code / Antigravity)
- **System Conventions Sanitization**: A compatibility transformation of OMP's exact `<system-conventions>` wrapper to `<conventions>`, retaining the enclosed instructions. Its scope is system/developer prompt text on ProtectedAGY requests; it does not alter tool data or explicit non-AGY bypass traffic. See [ADR 0003](docs/adr/0003-sanitize-system-prompt-conventions-tag-for-google-upstream.md).
- **Request Type Envelope Context**: OMP upstream omitted `requestType: "agent"` to prevent requests from being routed into Google's constrained agent quota bucket on consumer/free-tier accounts. CPA injects `requestType: "agent"` at the executor layer; on Antigravity Pro/paid tier accounts, this agent bucket is unconstrained and behaves normally without patching.
